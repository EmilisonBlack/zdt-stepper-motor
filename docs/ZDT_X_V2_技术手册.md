## 1. 产品概述

ZDT_X_V2 是张大头闭环伺服推出的第二代闭环步进电机驱动板，适用于 28/35/42/57 机座步进电机。

### 1.1 关键参数

| 参数 | 规格 |
|------|------|
| 主控芯片 | 32 位 ARM Cortex 系列 |
| MOS 管 | 8 管 H 桥 |
| 编码器分辨率 | 16384 线 |
| 供电电压 | 12 – 32V DC |
| 相电流 (X28/X35/X42) | 0 – 3000mA |
| 相电流 (X57) | 0 – 4000mA |
| 信号电平 | 3.3V – 28V (兼容 PLC NPN/PNP 24V) |
| 脉冲输入频率 | 20KHz+ |
| 串口通信波特率 | 160KHz 内部；**串口默认 115200 8N1** |
| 转速范围 | 0.1 – 3000.0+ RPM |
| 控制精度 | ≈0.08° |
| 细分设置 | 1 – 256 |

### 1.2 支持的通信接口

- **TTL** (3.3V/5V 逻辑电平) — 最常用，USB2TTL 直接连接
- **RS232** — 标准串口电平
- **RS485** — 差分传输，长距离
- **CAN** — 通过 OLED 切换 (P_Serial → CAN1_MAP)

### 1.3 固件版本识别

读取版本命令 `01 1F 6B`：
- 响应 `01 1F 00 C9 00 78 6B` → `0xC9` = 201 = `ZDT_X57_V2.0.1`
- 响应 `01 1F 00 78 6B` → `0x78` = 120 = `ZDT_X57_V1.2`（旧版）

> ⚠ **重要**: V2.0 和 V1.2 的自定义协议命令格式不同！本手册仅针对 **V2.0**。

## 2. 硬件接口与接线

### 2.1 TTL 接线（最常用）

| 驱动器引脚 | USB2TTL 转换器 |
|-----------|---------------|
| R/A/H | TXD (发送) |
| T/B/L | RXD (接收) |
| Gnd | GND (共地) |

```
USB2TTL          ZDT 驱动板
  TXD ─────────── R/A/H
  RXD ─────────── T/B/L
  GND ─────────── Gnd
```

> ⚠ **必须共地**！不共地会导致通信不稳定或完全无响应。

### 2.2 RS232 接线

| 驱动器引脚 | RS232 转换器 |
|-----------|-------------|
| R/A/H | TXD |
| T/B/L | RXD |
| Gnd | GND |

### 2.3 RS485 接线

| 驱动器引脚 | RS485 转换器 |
|-----------|-------------|
| R/A/H | A+ |
| T/B/L | B- |

> RS485 是差分传输，可不共地，但建议共地以提高稳定性。

### 2.4 使能信号 (En/En-)

驱动板提供使能信号接口：
- **En/En-**: 使能信号（光耦隔离）
- **En+**: 接 3.3V – 28V（或 PLC 24V）
- **En-**: 接 GND（低电平有效）
- 当 En 为低电平 (0V) → 使能 → 电机锁定
- 当 En 为高电平 (3.3V/24V) → 不使能 → 电机自由

如果不需要硬件使能控制，可将 En+ 悬空或通过 OLED 将 `P_En` 设置为 `Hold`。

## 3. OLED 菜单配置（重中之重）

驱动器配有一块 OLED 显示屏和三个按键（Enter/+/−），所有通信相关的设置都在这里配置。

### 3.1 关键菜单项

| OLED 菜单项 | 选项 | 说明 |
|------------|------|------|
| `P_Serial` | **`UART_FUN`** ← 必须设置此项！ | 串口功能模式 |
| | `ESI_ALO` | ❌ 此为模拟信号模式，串口无响应 |
| | `RxTx_OFF` | ❌ 关闭串口 |
| | `CAN1_MAP` | CAN 通信模式 |
| `Response` | **`Receive`** ← 建议设置此项 | 响应模式 |
| | `None` | ❌ 不返回任何响应，无法读取参数 |
| | `Reached` | 仅到位后响应 |
| | `Both` | 即时+到位都响应 |
| `Checksum` | **`0x6B`** ← 最简单，推荐 | 固定校验字节 |
| | `XOR` | XOR 累加校验 |
| | `CRC-8` | CRC-8 校验 |
| | `Modbus` | Modbus-RTU CRC16 校验 |
| `UartBaud` | `115200` | 波特率，默认为 115200 |
| `ID_Addr` | `1` – `255` | 驱动器地址，默认 `1` |

### 3.2 必须检查的配置（新人必看！）

1. **`P_Serial` 必须设置为 `UART_FUN`**
   - 如果默认是 `ESI_ALO`，串口收发引脚被禁用，发任何命令都**没有响应**。
   - 这是最常见的问题：USB2TTL 连接正确但收不到回复。

2. **`Response` 必须设置为 `Receive`（或 `Both`/`Reached`）**
   - 如果默认是 `None`，驱动器**不返回任何响应**。
   - 读参数命令会超时，无法获取状态。

3. **`Checksum` 决定通信协议**
   - `0x6B` → **Emm_V5.0 自定义协议**，帧尾固定为 `0x6B`。
   - `Modbus` → **Modbus-RTU 协议**，帧尾为 CRC16。
   - 两端必须一致，否则对方会丢弃报文。

### 3.3 OLED 其他常用设置

- **`P_En`**: `Hold`（硬件使能引脚悬空时保持使能状态）
- **`StepLogic`**: 脉冲模式（脉冲控制时使用）
- **`O_Dir`**: 电机方向反转
- **`O_Set`**: 设置当前角度为机械零点
- **`Cal`**: 编码器校准（出厂后首次使用需执行一次）

## 4. 通信协议总览

ZDT_X_V2 固件支持 **两种独立协议**，由 OLED `Checksum` 菜单切换：

| 协议 | 校验方式 | 典型命令帧 | 适用场景 |
|------|---------|-----------|---------|
| **自定义 0x6B 协议** | 固定 `0x6B` / XOR / CRC-8 | `01 36 6B` | PC/单片机直连，简单高效 |
| **Modbus-RTU** | CRC16 | `01 04 00 36 00 03 B0 04` | PLC/组态软件/HMI 互联 |

> ⚠ **两种协议不能混用**！`Checksum` 设为 `0x6B` 时只认 0x6B 帧，设为 `Modbus` 时只认 CRC16 帧。

### 4.1 通用帧结构

```
[地址(1B)] [功能码(1B)] [参数(N B)] [校验(1B 或 2B)]
```

- **地址**: 1 – 255（0x01 – 0xFF），`0x00` 为广播地址
- **功能码**: 决定命令类型
- **参数**: 因命令而异
- **校验**: 0x6B 协议时为 1 字节；Modbus-RTU 时为 2 字节 CRC16

### 4.2 错误响应

当命令格式错误或不支持时，驱动器返回 **错误帧**：

```
[地址] [0x00] [0xEE] [0x6B]
```

具体响应示例（自定义协议）：
```
01 00 EE 6B    ← 命令错误（格式错误、参数越界等）
```

Modbus-RTU 模式下返回标准 Modbus 异常码。

## 5. 自定义 0x6B 协议详解

### 5.1 帧格式

```
[地址] [功能码] [参数...] [校验]
```

- **地址**: 1 字节
- **功能码**: 1 字节
- **参数**: 0 到多字节
- **校验**: 取决于 OLED `Checksum` 设置

#### 5.1.1 校验模式

当 `Checksum = 0x6B` 时：
- 帧尾固定为 `0x6B`，仅作为结束标记
- 例: `01 36 6B`

当 `Checksum = XOR` 时：
- 校验值 = 地址 ^ 功能码 ^ 参数1 ^ 参数2 ^ ...
- 例: 命令 `01 36`，XOR = `0x01 ^ 0x36 = 0x37`，帧为 `01 36 37`

当 `Checksum = CRC-8` 时：
- 使用 CRC-8 查表算法（见附录）

### 5.2 校验算法

#### 5.2.1 固定 0x6B

最简单，直接附加 `0x6B` 在帧尾：
```c
// 任何命令在末尾加上 0x6B 即可
uint8_t cmd[] = { addr, 0x36, 0x6B };
```

#### 5.2.2 XOR 校验

```c
unsigned char command_calXOR(unsigned char *p, unsigned char len)
{
    unsigned char i = 0, xorV = p[0];
    for(i = 1; i < len; i++) {
        xorV ^= (*(p + i));
    }
    return xorV;
}
// 例: 01 36 → XOR = 0x01 ^ 0x36 = 0x37 → 01 36 37
```

#### 5.2.3 CRC-8 校验

```c
const unsigned char crc8Table[256] = {
    0x00, 0x5E, 0xBC, 0xE2, 0x61, 0x3F, 0xDD, 0x83,
    0xC2, 0x9C, 0x7E, 0x20, 0xA3, 0xFD, 0x1F, 0x41,
    // ... 完整表见附录 ...
};

unsigned char CRC8(unsigned char *p, unsigned char len)
{
    unsigned char crc8 = 0;
    for(unsigned char i = 0; i < len; i++) {
        crc8 = crc8Table[crc8 ^ p[i]];
    }
    return ~crc8;
}
```

### 5.3 读参数命令

所有读命令格式统一为：

#### 5.3.1 读固件版本 (0x1F)

| 方向 | 数据 |
|------|------|

#### 5.3.8 读实时位置 (0x36) ✅ 已验证

| 方向 | 数据 |
|------|------|
| 发送 | `01 36 6B` |
| 响应 | `01 36 [方向] [位置32位 big-endian] 6B` |

**响应格式详解**:
```
字节0: 地址
字节1: 0x36
字节2: 方向 (0=正转, 非0=反转)
字节3-6: 位置值 (int32 big-endian), 单位 0.1°
字节7: 0x6B
```

**示例**:
```
TX: 01 36 6B
RX: 01 36 00 00 00 05 DC 6B
```
- 方向 = `0x00` (正转)
- 位置 = `0x000005DC` = 1500 → **150.0°**

```
RX: 01 36 01 00 00 1C 19 6B
```
- 方向 = `0x01` (反转)
- 位置 = `-0x00001C19` = -7193 → **-719.3°**

#### 5.3.9 读目标位置 (0x33) ⚠ 有坑

| 方向 | 数据 |
|------|------|
| 发送 | `01 33 6B` |
| 响应 | `01 33 [方向] [位置32位 big-endian] 6B` |

**示例**:
```
RX: 01 33 01 00 00 0E 10 6B
```
- 方向 = `0x01` (反转)
- 位置 = `-0x00000E10` = -3600 → **-360.0°**

### 5.4 控制/写命令

> ⚠ **控制命令与 V1.2 不兼容！** V2.0 的控制命令格式有重大变化。

#### 5.4.1 使能控制 (0xF3) ✅ 已验证

```
[地址] [0xF3] [0xAB] [使能] [同步] [0x6B]
```

| 字段 | 说明 |
|------|------|
| 使能 | `0x01`=使能锁定, `0x00`=不使能释放 |
| 同步 | `0x01`=等待到位返回, `0x00`=立即返回 |

**示例**:
```
01 F3 AB 01 00 6B   → 使能锁定，立即返回
01 F3 AB 00 00 6B   → 不使能释放，立即返回
```

**成功响应**: `01 F3 02 6B`  
**错误响应**: `01 00 EE 6B`

#### 5.4.2 力矩模式 (0xF5)

```
[地址] [0xF5] [方向] [加速度 Ma/s_H] [加速度 Ma/s_L] [电流 Ma_H] [电流 Ma_L] [同步] [0x6B]
```

| 字段 | 说明 |
|------|------|
| 方向 | `0x00`=CW, `0x01`=CCW |
| 加速度 | 单位 Ma/s，例 `0x03E8` = 1000Ma/s |
| 电流 | 单位 mA，例 `0x0320` = 800mA |
| 同步 | `0x01`=同步, `0x00`=异步 |

**示例**:
```
01 F5 00 03 E8 03 20 00 6B   → CW, 1000Ma/s, 800mA, 异步
```

#### 5.4.3 速度模式 (0xF6) ✅ 已验证 ⚠ **格式与 V1.2 不同！**

```
[地址] [0xF6] [方向] [加速度_H] [加速度_L] [转速×10_H] [转速×10_L] [同步] [0x6B]
```

| 字段 | 说明 |
|------|------|
| 方向 | `0x00`=CW, `0x01`=CCW |
| 加速度 | **16 位**，单位 0.1RPM/s，例 `0x03E8` = 1000 = **100.0 RPM/s** |
| 转速×10 | **16 位**，单位 0.1RPM，例 `0x4E20` = 20000 = **2000.0 RPM** |
| 同步 | `0x01`=同步, `0x00`=异步 |

**示例**:
```
01 F6 00 00 0A 00 64 00 6B   → CW, 10RPM/s, 10.0RPM, 异步
01 F6 01 03 E8 4E 20 00 6B   → CCW, 1000RPM/s, 2000.0RPM, 异步
```

**成功响应**: `01 F6 02 6B`  
**错误响应**: `01 00 EE 6B` 或 `01 F6 E2 6B`

> ⚠ **V2.0 与 V1.2 的关键区别**:
> - V2.0 速度命令是 **9 字节**（加速度 16 位 + 转速 16 位 + 同步），共 8+1=9 字节不含地址校验部分
> - V1.2 速度命令是 8 字节（加速度 8 位 + 转速 16 位 + 同步）
> - **写 V1.2 的 8 字节帧会返回 `01 00 EE 6B` 错误！**

#### 5.4.4 梯形曲线位置模式 (0xFB)

```

```

| 字段 | 说明 |

| 方向 | `0x00`=CW, `0x01`=CCW |
| 转速×10 | 单位 0.1RPM，`0x4E20`=2000.0RPM |
| 位置×10 | **32 位**，单位 0.1°，最大 ±3600.0°（10圈） |

| 同步 | `0x00`=异步 |

**示例**:

```
→ CCW, 2000.0RPM, -3600.0° (0x00008CA0=36000), 绝对位置, 同步
```

#### 5.4.5 直通限速位置模式 (0xFD) ✅ 已验证 ⚠ **V2.0 格式**

```
[地址] [0xFD] [方向] [加加速度1_H] [加加速度1_L] [加加速度2_H] [加加速度2_L] [转速×10_H] [转速×10_L] [位置×10_32bit big-endian] [绝对/相对] [同步] [0x6B]
```

## 6. Modbus-RTU 协议说明

当 OLED `Checksum` 设为 `Modbus` 时，驱动器使用标准 Modbus-RTU 协议。

### 6.1 基本配置

- **波特率**: 115200（由 OLED `UartBaud` 设置）
- **数据格式**: 8N1
- **地址**: 1–255
- **校验**: CRC16 (Modbus 标准)

### 6.2 读命令 (功能码 0x04)

读参数使用 Modbus 功能码 `0x04`（读输入寄存器）。

**通用格式**:
```
[地址] [0x04] [寄存器地址_H] [寄存器地址_L] [寄存器数量_H] [寄存器数量_L] [CRC16_L] [CRC16_H]
```

#### 常用读寄存器地址

| 参数 | 寄存器地址 | 数量 | 返回 | 说明 |
|------|-----------|------|------|------|
| 版本 | 0x0010 | 2 | 4 字节 | ASCII 版本号 |
| 状态 | 0x0050 | 1 | 2 字节 | 同 0x3A 标志位 |
| 回零状态 | 0x0052 | 1 | 2 字节 | 同 0x3B |
| 位置 | 0x003C | 3 | 6 字节 | 方向+位置×0.1° |
| 目标位置 | 0x0040 | 3 | 6 字节 | 方向+位置×0.1° |
| 位置误差 | 0x0044 | 2 | 4 字节 | 方向+误差×0.01° |
| 转速 | 0x0038 | 3 | 6 字节 | 方向+转速×0.1RPM |
| 目标转速 | 0x0046 | 3 | 6 字节 | 方向+转速×0.1RPM |
| 负载率 | 0x004A | 3 | 6 字节 | 方向+负载×0.01% |
| 电流 | 0x004E | 1 | 2 字节 | 有效电流 mA |
| 总线电压 | 0x0024 | 1 | 2 字节 | mV |
| 设置电流 | 0x0027 | 1 | 2 字节 | mA |
| 实际相电流 | 0x0026 | 1 | 2 字节 | mA |
| 编码器 | 0x0029 | 1 | 2 字节 | 0-16383 |
| 温度 | 0x0030 | 1 | 2 字节 | ℃ |
| 电机参数 | 0x0014 | 8 | 16 字节 | PID 参数 |
| 综合状态 | 0x0078 | 17 | 34 字节 | 所有参数一次读出 |

### 6.3 写命令 (功能码 0x10)

写参数使用 Modbus 功能码 `0x10`（写多个寄存器）。

#### 常用写寄存器地址

| 同步 | 0x00FF | 1 | `66` | 同 0xFF |
| 速度模式 | 0x00F6 | 7 | 方向+加加速度+转速+... | 14 字节 |
| 梯形位置 | 0x00F0 | 5 | 方向+转速+位置+... | 10 字节 |
| 直通位置 | 0x00E6 | 4 | 方向+加加速度+转速+... | 8 字节 |
| 力矩模式 | 0x00E2 | 4 | 方向+加速度+电流+... | 8 字节 |

| ID | 0x00A2 | 2 | 保存+新地址 | 4 字节 |

### 6.4 Modbus 踩坑记录

> ⚠ **实际测试发现 Modbus 写命令返回异常码**，问题可能是：
> 1. 写寄存器数量不对（手册上有些写命令的寄存器数量容易搞错）
> 2. CRC16 计算错误
> 3. 驱动器的 Modbus 实现可能与标准有差异
> 
> **建议**: 优先使用自定义 0x6B 协议进行开发，Modbus 协议作为 PLC/HMI 互联时的备选方案。

## 7. 踩坑实录 & 解决方案

以下问题均为实际开发中遇到并解决的真实问题。

### 坑 1: 串口发命令无响应

**症状**: USB2TTL 连接正确（自收发测试正常），但驱动器不返回任何数据。

**原因**: OLED 菜单中 `P_Serial` 默认是 `ESI_ALO`（模拟信号模式），此时串口收发引脚被禁用。

**解决**: 
```
OLED 菜单 → P_Serial → 选择 UART_FUN → 保存
```

### 坑 2: 发送命令后返回值全是乱码

**症状**: 收到的数据看起来像乱码或错的字节序列。

**原因**: `Checksum` 设置不匹配。发送方用 `0x6B` 但驱动器设置为 `Modbus`，或反之。

**解决**: 确保 OLED `Checksum` 与程序中使用的校验方式一致。

### 坑 3: 发送写命令（控制命令）返回 `01 00 EE 6B`

**症状**: 读命令正常，但使能、速度模式、位置模式等写命令都返回错误。

**原因**: **ZDT_X_V2.0 的控制命令格式与 V1.2 不同！** 如果参考了 Emm_V5.0 或 V1.2 的资料来编写控制命令，帧长度可能不对。

**速度模式格式对比**:

| 版本 | 命令格式 | 长度 |
|------|---------|------|
| V1.2 | `[addr][F6][dir][vel_H][vel_L][acc8][sync][6B]` | 8 字节 |
| **V2.0** | `[addr][F6][dir][acc16_H][acc16_L][vel×10_H][vel×10_L][sync][6B]` | **9 字节** |

V2.0 速度模式下：
- 加速度是 **16 位**（不是 8 位）
- 速度单位是 **0.1 RPM**（需要 ×10）
- 加速度在速度之前

**解决**: 严格按照第 5 章的 V2.0 命令格式发送。

### 坑 4: 两条命令间隔太短导致被合并

**症状**: 连续发两条命令，第二条返回 `01 00 EE 6B` 错误。

**原因**: 驱动器将两条命令的首尾识别为同一帧。

**解决**: 两条命令之间至少延时 **1–10ms**。建议加 5ms 以上延时。

> 官方文档明确说明："两条命令之间的发送需要延迟 1-10ms，否则连着发的话，闭环可能判定为一条命令，返回 `01 00 EE 6B` 错误命令。"

### 坑 5: 读目标位置 (0x33) 和读位置误差 (0x37) 解析错误

**症状**: 读出的目标位置和误差值异常大（如 1677721.6°）。

**原因**: 这些命令的响应格式与 0x36（读位置）**不一致**。虽然响应都带方向字节，但 0x37 的误差单位是 **0.01°**（除以 100），而 0x36 的位置单位是 **0.1°**（除以 10）。

**总结读取响应格式**:

| 命令 | 字节数 | 解析方式 | 单位 |
|------|--------|---------|------|
| 0x36 读位置 | 8 B | `[dir] [pos32]` | 0.1° |
| 0x33 读目标 | 8 B | `[dir] [pos32]` | 0.1° |
| 0x34 读绝对 | 8 B | `[dir] [pos32]` | 0.1° |
| 0x35 读转速 | 6 B | `[dir] [spd16]` | 0.1 RPM |
| 0x37 读误差 | 8 B | `[dir] [err32]` | **0.01°** |
| 0x3A 读标志 | 4 B | `[flags]` | — |
| 0x3B 读回零 | 4 B | `[status]` | — |
| 0x24 读电压 | 5 B | `[mV16]` | mV |
| 0x27 读电流 | 5 B | `[mA16]` | mA |
| 0x31 读编码 | 5 B | `[val16]` | 原始值 |

> 注意 0x35 读转速是 6 字节（方向+16位转速），不是 8 字节！

### 坑 6: 读转速方向解析误区

**症状**: 读转速返回 `01 35 01 4E 20 6B`，将整个数据当作有符号32位整数解析得到负数。

**原因**: 转速响应中，**方向字节和转速值是分开的**。方向字节 `0x01` 表示 CCW，然后转速值 `0x4E20` = 20000（无符号）→ 2000.0 RPM，真正的方向由方向字节单独表示。

**正确做法**:
```c
int dir = rx[2];  // 0=CW, 非0=CCW
uint16_t raw = (rx[3] << 8) | rx[4];
float rpm = raw / 10.0f;
if (dir) rpm = -rpm;
```

### 坑 7: 新板子首次上电显示 "Not Cal"

**症状**: OLED 显示 "Not Cal"，电机无法正常运行。

**原因**: 编码器未校准。

**解决**: 
```
OLED 菜单 → 找到 "Cal" → Enter → 等待完成
```
或发送校准命令:
```
01 06 45 6B
```

### 坑 8: 同一个命令读出的数值每次都变

**症状**: 电机静止时，读位置/编码器值每次都不一样，漂移几度。

**原因**: 
1. 电机未使能（Encoder 值在没有励磁时可能会漂移）
2. 编码器需要校准
3. 读数间隔正常波动（0.1° 级别）

**解决**: 使能电机后读数；执行编码器校准。

### 坑 9: USB2TTL 转接板质量问题

**症状**: 偶尔通信失败，收到的数据不完整或 CRC 校验错误。

**原因**: USB2TTL 转接板质量参差不齐，有些芯片（如 CH340G 仿冒品）不稳定。

**建议**: 
- 使用正品 FT232 或 CP2102 芯片的 USB2TTL
- 降低波特率（如 9600/19200）增加稳定性
- 检查接线，TX/RX 不要接反

### 坑 10: 总线电压读数为 0 或异常

**症状**: `zdt_ReadBusVoltage` 返回 0 或明显不对的值。

**原因**: 可能是供电问题或 ADC 采样异常。

**解决**:
- 检查供电是否在 12–32V 范围内
- 检查 OLED 是否显示正常电压
- 如果 OLED 也显示异常，可能是硬件故障

### 坑 11: Modbus 写命令返回异常码

**症状**: Modbus 读命令（0x04）正常工作，但写命令（0x10）返回异常码。

**原因**: 可能性较多：
1. 写命令的寄存器数量（Byte count）计算错误
2. 数据值格式不对（如需要大端序但用了小端序）
3. CRC16 计算有误
4. 写入的值超出范围

**建议**: 
- 先用 Modbus Poll 测试写命令
- 与自定义 0x6B 协议交叉验证
- 检查 CRC16 计算（使用标准 Modbus CRC16 算法）

## 8. SDK 编写指南

### 8.1 架构设计

一个完整的 SDK 应包含以下层次：

```
┌──────────────────────────────────────┐
│          用户应用层                    │
│  (位置控制/速度控制/回零/参数读取)     │
├──────────────────────────────────────┤
│          SDK 函数层                   │
│  (zdt_Enable, zdt_SpeedMode, ...)    │
├──────────────────────────────────────┤
│          协议收发层                    │
│  (zdt_Transmit, cmd_read, cmd_write) │
├──────────────────────────────────────┤
│          平台抽象层                    │
```

### 8.3 核心实现要点

#### 8.3.1 命令发送

发送命令时，按以下步骤：
1. 组装命令帧（地址 + 功能码 + 参数）
2. 追加校验字节（0x6B）
3. 调用 `zdt_platform_uart_send` 发送
4. 调用 `zdt_platform_uart_recv` 接收响应
5. 验证响应地址和校验
6. 解析参数

#### 8.3.2 超时处理

读命令建议设置 200ms 超时。对于会执行较长时间的命令（如同步回零），超时可适当延长。

#### 8.3.3 命令间隔

发送两条命令之间应至少延时 **5ms**。可以在每个 `zdt_Transmit` 发送前调用 `zdt_platform_delay(5)` 或发送后调用。

#### 8.3.4 返回值约定

| 返回值 | 含义 |
|--------|------|
| 0 | 成功 |
| -1 | 串口通信失败 |
| -2 | 地址不匹配 |
| -3 | 校验错误 |
| -4 | 响应超时 |

### 8.4 关键命令实现细节

#### 速度模式

```c
// ZDT_X V2.0 格式: 9 字节
// [addr] [0xF6] [dir] [accel16_H] [accel16_L] [speed×10_H] [speed×10_L] [sync] [0x6B]
int zdt_SpeedMode(uint8_t dir, uint16_t rpm, uint16_t accel, bool sync)
{
    uint16_t speed10 = rpm * 10;          // 转为 0.1 RPM
    uint8_t cmd[] = {
        g_addr, 0xF6, dir,
        (accel >> 8) & 0xFF, accel & 0xFF,
        (speed10 >> 8) & 0xFF, speed10 & 0xFF,
        sync ? 1 : 0,
        0x6B
    };
    return zdt_Transmit(cmd, sizeof(cmd), rx, &rlen);
}
```

#### 位置模式

```c
// ZDT_X V2.0 格式: 15 字节
// [addr] [0xFD] [dir] [accel1_H] [accel1_L] [accel2_H] [accel2_L] 
// [speed×10_H] [speed×10_L] [pos×10_32bit big-endian] [abs] [sync] [0x6B]
int zdt_PositionMode(uint8_t dir, uint16_t rpm, uint16_t accel1, uint16_t accel2,
                     int32_t pos_deg_x10, bool absolute, bool sync)
{
    uint8_t cmd[15];
    cmd[0]  = g_addr;
    cmd[1]  = 0xFD;
    cmd[2]  = dir;
    cmd[3]  = (accel1 >> 8) & 0xFF; cmd[4] = accel1 & 0xFF;
    cmd[5]  = (accel2 >> 8) & 0xFF; cmd[6] = accel2 & 0xFF;
    uint16_t speed10 = rpm * 10;
    cmd[7]  = (speed10 >> 8) & 0xFF; cmd[8] = speed10 & 0xFF;
    cmd[9]  = (pos_deg_x10 >> 24) & 0xFF;
    cmd[10] = (pos_deg_x10 >> 16) & 0xFF;
    cmd[11] = (pos_deg_x10 >> 8) & 0xFF;
    cmd[12] = pos_deg_x10 & 0xFF;
    cmd[13] = absolute ? 1 : 0;
    cmd[14] = sync ? 1 : 0;
    return cmd_write(cmd, 15);  // 内部追加 0x6B
}
```

## 9. 平台移植指南

### 9.1 移植到 Windows

使用 Win32 API：
- `CreateFileA` 打开串口
- `WriteFile` 发送数据
- `ReadFile` 接收数据
- `Sleep` 延时

详见 `examples/platform_win32.c`。

**关键注意点**:
- 串口路径格式: `\\.\COM9`
- 配置: 115200, 8N1
- 禁用 DTR/RTS 流控: `DTR_CONTROL_DISABLE`, `RTS_CONTROL_DISABLE`
- 读超时: `ReadIntervalTimeout = MAXDWORD`, `ReadTotalTimeoutConstant = 100`

### 9.2 移植到 Linux

使用 POSIX termios API：
- `open("/dev/ttyUSB0", ...)` 打开串口
- `write` 发送数据
- `read` 接收数据
- `usleep` / `nanosleep` 延时

配置示例:
```c
struct termios tty;
tcgetattr(fd, &tty);
cfsetospeed(&tty, B115200);
cfsetispeed(&tty, B115200);
tty.c_cflag = CS8 | CLOCAL | CREAD;
tty.c_iflag = IGNPAR;
tty.c_oflag = 0;
tty.c_lflag = 0;
tcflush(fd, TCIFLUSH);
tcsetattr(fd, TCSANOW, &tty);
```

### 9.3 移植到 STM32

使用 STM32 HAL 库：
- `HAL_UART_Transmit` 发送
- `HAL_UART_Receive` 接收（或 DMA + 超时）
- `HAL_Delay` 延时

```c
int zdt_platform_uart_send(const uint8_t *data, uint16_t len) {
    return HAL_UART_Transmit(&huart1, (uint8_t*)data, len, 100) == HAL_OK ? len : 0;
}

int zdt_platform_uart_recv(uint8_t *buf, uint16_t len, uint32_t timeout_ms) {
    return HAL_UART_Receive(&huart1, buf, len, timeout_ms) == HAL_OK ? len : 0;
}

void zdt_platform_delay(uint32_t ms) {
    HAL_Delay(ms);
}
```

### 9.4 移植到 Arduino

```c
int zdt_platform_uart_send(const uint8_t *data, uint16_t len) {
    return Serial.write(data, len);
}

int zdt_platform_uart_recv(uint8_t *buf, uint16_t len, uint32_t timeout_ms) {
    uint32_t start = millis();
    uint16_t idx = 0;
    while ((millis() - start) < timeout_ms) {
        if (Serial.available()) {
            buf[idx++] = Serial.read();
            if (idx >= len) break;
        }
    }
    return idx;
}

void zdt_platform_delay(uint32_t ms) {
    delay(ms);
}
```
