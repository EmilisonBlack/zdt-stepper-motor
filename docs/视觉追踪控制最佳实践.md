# 视觉追踪控制最佳实践

> **适用场景**: 步进电机 + 视觉反馈的连续追踪控制  
> **硬件**: ZDT_X_V2 闭环步进驱动器 + USB2TTL 串口  
> **协议**: 自定义 0x6B 协议 (Emm_V5.0)  
> **控制频率**: ~20Hz (50ms 周期, 受串口带宽限制)  
> **最后更新**: 2026-07-22

---

## 1. 问题定义

### 1.1 典型场景

摄像头检测到目标，返回目标在画面中的像素位置。控制器需要驱动电机，使目标始终位于画面中心。

```
                    像素偏差 (带噪声)
摄像头 ──────────────────────→  控制器
                                      │
                                      │ 速度命令 (串口)
                                      ↓
                               ZDT 步进驱动器
                                      │
                                      │ 驱动电机
                                      ↓
                              云台/平台转动
                                      │
                                      │ 目标在画面中移动
                                      └──→ 摄像头 (闭环)
```

### 1.2 核心困难

| 问题 | 说明 |
|------|------|
| **不知道精确角度** | 摄像头只返回像素偏差，无法直接换算为精确角度 |
| **测量噪声** | 像素检测抖动、光照变化引入噪声 |
| **运动目标** | 目标可能连续运动，无法一次性给定位移量 |
| **通信延迟** | 串口 115200bps，单次读写约 15-20ms |
| **控制频率低** | 50ms 周期内电机可移动 30°+（在高速时） |

### 1.3 三个考评指标

1. **平滑度** — 速度变化是否柔和，无急加速/急减速
2. **追踪速度** — 从目标出现到稳定跟踪的时间
3. **稳态误差** — 稳定后的残余定位误差

这三个指标互相制约：速度越快→过冲越大→误差越大；越平滑→响应越慢。

## 2. 方案演进

### 2.1 ❌ 方案一: 位置模式 (0xFD)

**思路**: 直接用绝对位置模式，每次设定精确目标角度。

**失败原因**: 
- 控制器不知道精确角度（只有像素偏差）
- 频繁更新目标会重置驱动器内部的轨迹规划器，导致震荡

```python
# ❌ 位置模式不适合持续修正场景
motor.position_abs(degrees=90)   # 第一次
motor.position_abs(degrees=95)   # 0.1s 后第二次 → 轨迹被重置 → 抖动
```

### 2.2 ❌ 方案二: 高速 PID + 速度模式

**思路**: 用上位机 PID 计算目标转速，通过速度模式执行。

**失败原因**:
- 串口延迟导致反馈滞后，高增益下必然震荡
- 力矩模式做精定位时，克服静摩擦的电流会使电机高速旋转
- 状态机频繁切换导致电机加减速跟不上

### 2.3 ✅ 方案三: 低增益比例 + 速度模式 (最终方案)

**思路**: 
- 转速与像素偏差成正比（低增益，天然防震荡）
- 最低保持 1RPM 蠕动到位
- 到位后停止 + 保持力矩

---

## 3. 最终方案

### 3.1 控制律

```
speed = clamp(KP × |pixel_error|, MIN_SPEED, MAX_SPEED)
direction = sign(pixel_error)   # 正=右=CW, 负=左=CCW
```

**仅需 3 个参数**:

| 参数 | 推荐值 | 单位 | 说明 |
|------|--------|------|------|
| `KP` | 0.04–0.06 | RPM/像素 | 比例增益，唯一需要调节的参数 |
| `MAX_SPEED` | 25–30 | RPM | 最高转速，受 20Hz 控制频率限制 |
| `MIN_SPEED` | 1 | RPM | 最低蠕动速度，进入死区的关键 |
| `DEADBAND` | 3–5 | 像素 | 死区宽度，噪声容忍度 |

### 3.2 特性分析

#### 稳态跟踪误差

当目标匀速运动时，P 控制器必然存在跟踪滞后：

```
跟踪误差(°) = 目标速度(°/s) / (KP(RPM/px) × 像素密度(px/°) × 6)
```

以 `KP=0.05`, `640px/60°FOV` 为例：

| 目标速度 | 理论误差 | 实测误差 |
|---------|---------|---------|
| 静止 | 0° | <0.5° |
| 10°/s | 1.9° | ~2° |
| 30°/s | 5.6° | ~6° |
| 55°/s | 10.3° | ~11° |

#### 阶跃响应 (目标跳变)

| 跳变幅度 | 到位时间 | 稳态精度 |
|---------|---------|---------|
| 50° | ~1.0s | ±0.5° |
| 100° | ~1.5s | ±0.3° |
| 160° | ~1.8s | ±0.3° |

> 到位时间 ≈ 跳变幅度 / (MAX_SPEED × 6 × 0.7)  
> 其中 0.7 为加减速效率因子

#### 平滑度

无震荡、无抖动、无急加速/急减速。速度变化完全由比例律 + 驱动器内部加减速控制。

## 4. 与位置模式的对比

| 指标 | 位置模式 (0xFD) | 速度模式 + 比例 (本方案) |
|------|---------------|----------------------|
| 需要精确角度 | ✅ 是 | ❌ 否，只需像素偏差 |
| 单次到位精度 | ±0.1° | ±0.5° |
| 连续运动追踪 | ❌ 轨迹被重置 | ✅ 天生适合 |
| 噪声抑制 | ❌ 噪声→位置抖动 | ✅ 低增益自然滤波 |
| 震荡风险 | 高（更新太快时） | 极低（低增益保证） |

**结论**: 对于视觉追踪场景，速度模式 + 低增益比例控制是正确选择。  
位置模式适用于"已知精确目标角度 + 单次运动"的场景。

## 5. 参数调节指南

### 5.1 KP 的影响

| KP 值 | 响应速度 | 稳态误差 | 震荡风险 |
|-------|---------|---------|---------|
| 0.03 | 慢 | 大 | 极低 |
| **0.05** | **适中** | **可接受** | **极低** ⭐推荐 |
| 0.08 | 快 | 小 | 中等 |
| 0.12+ | 很快 | 很小 | 高 |

**调节方法**: 从 0.03 开始，每次 +0.01，观察追踪是否出现震荡。出现震荡则回调。

### 5.2 MAX_SPEED 的影响

| MAX_SPEED | 到位时间(100°) | 过冲 | 说明 |
|-----------|--------------|------|------|
| 20 RPM | ~2.2s | 很小 | 最安全 |
| **28 RPM** | **~1.5s** | **可控** | **⭐推荐** |
| 35 RPM | ~1.2s | 中等 | 噪声大时可能震荡 |
| 50 RPM+ | <1.0s | 大 | 20Hz 控制跟不上 |

### 5.3 MIN_SPEED 的作用

- 设为 1 RPM：电机爬行到目标，精度最高
- 设为 0 RPM：可能导致频繁启停（速度指令为 0 时电机自由）
- 设为 3 RPM+：残余误差增大（>3°）

### 5.4 死区 (DEADBAND)

- 设为目标在画面中心 ±N 像素时的容忍范围
- 太小 → 噪声触发频繁启停
- 太大 → 目标偏离中心过多
- 推荐 3-5 像素（取决于像素噪声水平）

## 6. Python 实现

### 6.1 核心控制器

```python
class PixelTracker:
    """基于像素偏差的比例速度追踪控制器"""

    def __init__(self, port='COM9'):
        self.motor = ZDTStepper(port)

        # ─── 唯一需要调的参数 ───
        self.KP = 0.05           # RPM/像素
        self.MAX_SPEED = 28      # RPM
        self.MIN_SPEED = 1       # RPM
        self.DEADBAND_PX = 3     # 像素

    def step(self, pixel_error: float):
        """执行一步追踪

        Args:
            pixel_error: 目标在画面中的像素偏差 (正=偏右)
        """
        pos = self.motor.read_position()

        if abs(pixel_error) < self.DEADBAND_PX:
            # 在死区内: 停止 + 保持力矩
            self.motor.stop()
            self.motor.torque_mode(dir_cw=True, current_ma=25, accel=200)
            return {'pos': pos, 'mode': 'hold'}

        # 比例速度 (带限幅)
        speed = abs(pixel_error) * self.KP
        speed = max(self.MIN_SPEED, min(self.MAX_SPEED, speed))

        # 执行
        self.motor.speed_mode(
            dir_cw=(pixel_error > 0),
            rpm=int(speed),
            accel=1500
        )

        return {'pos': pos, 'speed': speed, 'mode': 'track'}
```

### 6.2 完整使用示例

```python
from pixel_tracker import PixelTracker

tracker = PixelTracker(port='COM9')
tracker.motor.enable()

# 每帧调用一次 (20Hz)
for each_camera_frame:
    pixel_error = detect_target()  # 你的视觉检测函数
    tracker.step(pixel_error)
```

## 7. 物理限制与展望

### 7.1 当前限制

| 限制项 | 数值 | 原因 |
|-------|------|------|
| 最高追踪速度 | ~55°/s | 串口 50ms 周期 × 28RPM |
| 最低到位精度 | ±0.3° | 像素量化 + 死区 |
| 控制频率 | 20Hz | 串口读写延迟 |

### 7.2 突破限制

| 方案 | 预期提升 | 代价 |
|------|---------|------|
| **换 CAN 总线** | 控制频率 200Hz+, 速度可达 100RPM+ | 需 CAN 转换器硬件 |
| **提高波特率** | 少量提升 | 稳定性下降 |
| **专用控制板** | kHz 级控制 | 需额外硬件开发 |

### 7.3 适用场景

✅ **适合**:
- 视觉追踪云台
- 目标跟踪系统
- 需要平滑连续运动的定位
- 反馈带噪声的场景

❌ **不适合**:
- 需要亚角秒级精密定位
- 超高速目标追踪 (>100°/s)
- 要求即时响应的安全系统
